I already pay for Claude Code. Why do I need Seatkey?

So your subscription works beyond the terminal.

Seatkey runs a regular OpenAI endpoint on your computer, and behind it sits the very agent you already pay for: Claude Code, Codex or Cursor. Paste the address into Obsidian, Open WebUI or your own script, and they run on your subscription, with no second bill.

01 — the problem

A subscription doesn't roll over.
What you don't use before the reset is gone.

Subscription limits come in fixed periods: five hours and a week for Claude Code, a week for Codex, a month for Cursor. Whatever is left doesn't carry over. While you're away from the terminal, what you paid for just waits for the reset. Meanwhile your notes app and your scripts want an “OpenAI API”, which means a second bill.

    04 — beyond the subscription
    
      
    The same address fronts
    everything else you pay for.
    
      
    
        Your subscription isn't your only access. An OpenAI-compatible provider,
        a local model, a company service with its own token: Seatkey keeps them
        behind the same local address. Their secrets live in the OS keychain
        instead of being scattered across the configs of a dozen apps.
      
    
    
    

    

    
    
      
    
        
    Three kinds of endpoints
    
        
    Behind an address sits a subscription agent, as before, or an OpenAI-compatible provider (DeepSeek, OpenRouter, local Ollama and LM Studio), or any HTTP service. Proxy endpoints require a key, send no CORS headers and don't follow redirects.
    
      
    
      
    
        
    An endpoint that doesn't die
    
        
    An agent endpoint can have a fallback provider: if the quota runs out or the agent is unavailable, the same address completes the request through it. The switch happens only before the first token, and the log shows the request on both lines.
    
      
    
      
    
        
    Secrets in the OS keychain
    
        
    Tokens for external services live in one place, with expiry dates in plain sight and a reminder before they run out. The secret never ends up in a config file or a problem report.
    
      
    
      
    
        
    The agent calls your services itself
    
        
    Credentials you mark become the agent's tools: it can reach Jira or Jenkins without ever seeing the token, because Seatkey makes the request. Every such call stays in the log: method, path, status and whose token was used.
    
      
    
    
    
  
    

    


    
  
    
    
    
      
    05 — what happens inside
    
      
    Every request is visible.
    Only what you send out
    leaves the machine.
    
    
    
  
    
  
    
    
    
      
      
    
        
    Who asked, with which model, how long it took and how it ended: the log updates live while the app runs.
    
        
    Request bodies aren't stored by default. Only metadata goes to the database. Prompts and responses appear there only if you turn that on yourself, and they stay in a local SQLite file.
    
        
    The server listens on 127.0.0.1, and there's no telemetry. A request to the agent never leaves the machine. It goes out only where you chose to send it: to a provider behind a proxy endpoint, to a fallback upstream, to Jira through an agent tool. Each such call is a separate line in the log.
    
        
    The only request Seatkey makes on its own initiative is an anonymous update check, and you can turn it off.
    
      
    
    
    
  
    

    


    
  
    
    
    
      
    06 — before you download
    
      
    What's fair to say up front.
    
    
    
    
    
      
    
        
    macOS only, for now
    
        
    There are builds for Apple Silicon and Intel Macs. The code is cross-platform, but there are no Windows or Linux builds yet.
    
      
    
      
    
        
    The interface is in Russian
    
        
    Section names are in English, but the rest of the app's interface is in Russian for now. The screenshots on this page show it as it is.
    
      
    
      
    
        
    It doesn't replace your subscription
    
        
    You need an installed, paid agent: Claude Code, Codex CLI or Cursor Agent. Seatkey uses yours, not one of its own. You can also set up an endpoint to a provider with your own key, but then you pay that provider's prices, and it's no longer “free on top of your subscription”.
    
      
    
      
    
        
    Not the whole OpenAI API
    
        
    No embeddings, audio or image generation. Cursor doesn't accept images as input either. Anything the CLI can't do comes back as a clear error before any quota is spent, never as silence. Parameters that are accepted but have no effect are listed in the X-Seatkey-Ignored header. Reasoning effort, on the other hand, does reach the agent, and X-Seatkey-Effort tells you which level the request actually ran with.
    
      
    
      
    
        
    One key, one computer
    
        
    The license is time-limited, tied to the machine and checked offline. Without a key the app runs, but requests to models don't go through.
    
      
    
    
    
  
    

    


    
  
    
    
    
      
    07 — questions
    
      
    What people ask first.
    
    
    
    
    
      
    
        Doesn't this break the subscription terms?
        
    
          
    Seatkey runs the provider's official CLI as a subprocess: on your machine, under your account, with your subscription. It doesn't emulate their HTTP API, doesn't read or forward their tokens and doesn't open access to anyone but you. The server listens only on 127.0.0.1.
    
          
    It's exactly what you do by hand in the terminal, except your app makes the call instead of you. Still, read the terms of your plan yourself: they differ between providers and change over time.
    
        
    
      
    
      
    
        How is this better than a regular API key?
        
    
          
    An API key bills per token, so every question from your notes costs extra. The subscription is already paid for and counts nothing; Seatkey just lets you reach it.
    
          
    As a bonus, there's no second account to set up, no balance to watch and no secret key to spread across a dozen apps' settings. Each app gets its own local key, and you can revoke it without touching the rest.
    
        
    
      
    
      
    
        Do my conversations go anywhere?
        
    
          
    Not while an agent sits behind the address: everything happens between your apps and your own agent on this machine. Request history is kept in a local database, and request bodies aren't stored unless you turn that on.
    
          
    Exceptions are yours to create, explicitly: an endpoint to an external provider, a fallback upstream on an agent endpoint, a credential marked as an agent tool. Then the request does go where you sent it, and the log shows it as a separate line, along with whose token was used.
    
          
    The only network request Seatkey makes on its own is an anonymous update check on GitHub, with no identifiers. You can turn it off in settings.
    
        
    
      
    
      
    
        What if the agent updates and something breaks?
        
    
          
    Seatkey talks to the CLI the way a person does: it runs the binary and reads its output. So an agent update usually breaks one thing rather than everything at once.
    
          
    When it happens, you can see what broke: the failed request stays in the log with its error text, and the Problem Report bundles versions, diagnostics and recent requests into a single file. Seatkey's own updates install only when you press the button; it never starts installing on its own, because a restart would cut off your apps' requests.
    
        
    
      
    
      
    
        Will there be Windows and Linux builds?
        
    
          
    The code is cross-platform and the app builds on both; the builds just aren't published. If you need one for your system, open an issue: demand sets the order.
    
        
    
      
    
      
    
        How much does it cost?
        
    
          
    It's early access. The app is paid: keys are issued on request and tied to your computer, and terms are agreed one-on-one.
    
          
    You can download it and look around right now. The interface, settings and diagnostics work without a key; only the model requests themselves are locked.
